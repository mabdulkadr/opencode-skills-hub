# 6-Month Plan — One Career Story (180 Days MAX)

The learner is one person on one journey: junior IT support → troubleshooting → docs →
meetings → technical decisions → presentations and interviews. Never extend beyond Day 180.

| Month | Days | Level | Theme (IT progression) | Grammar serves the situation |
|---|---|---|---|---|
| 1 | 001–030 | B1 | Operations Fluency: standups, tickets, handovers with blockers | Complex sentences + linkers: `Although the backup completed, replication is lagging, so I have escalated...` |
| 2 | 031–060 | B2 | Incidents & Troubleshooting: cause chains, workarounds, escalations | Passive + conditionals I/II: `The patch was rolled back because... / If we deferred the reboot, we could protect the backup window.` |
| 3 | 061–090 | B2 | Docs-as-Code: README, runbooks, GitHub, changelogs, policies | Sequencers + nominalization intro: `Deployment fragility was caused by...` |
| 4 | 091–120 | C1 | Meetings & Negotiation: scope, deadlines, stakeholders, dissent | Hedging + concession: `While I agree on the urgency, deferring X would protect Y.` |
| 5 | 121–150 | C1 | Architecture, Security, Cost: ADR, threat model, optimization memo | Mixed conditionals + stance: `Had we pinned the version, we would not have... / The evidence suggests...` |
| 6 | 151–180 | C2 | Leadership & Career: strategy, panel Q&A, negotiation, portfolio reflection | Synthesis + executive summary: `In short, we recommend A over B because..., with rollback by...` |

## Weekly practical output (every 7 days: 07, 14, 21, 30, 35, ... 180)

Each review day keeps the locked sections with adapted titles and measures the week's
single transferable skill (not recall). Weekly outputs rotate:
Week 1: introduce yourself and your team · Week 2: describe the IT department ·
Week 3: describe devices and locations · Week 4: give a simple IT update (+ M1 mini-project) ·
then: troubleshooting guide → README section → meeting simulation → technical comparison → presentation.

## Monthly mini-projects (performance, not tests)

- **M1 (Day 030):** Explain a simple IT system or tool (one page, e.g. Intune patches 3,000 devices).
- **M2 (Day 060):** Troubleshooting guide (reproduce → workaround → escalate).
- **M3 (Day 090):** Documentation for a small project (README section + issue).
- **M4 (Day 120):** Simulate a team meeting (agenda, standup, action items).
- **M5 (Day 150):** Explain a technical solution in a modern domain (e.g. Veeam backup to cloud).
- **M6 (Day 180):** Capstone — present a complete project (problem, solution, docs, update, 3-min talk, 5 Q&A).

## Capstone rubric (2/1/0 each)

Clarity, Accuracy, Fluency, Technical Vocabulary, Communication Effectiveness,
Writing Quality, Professionalism → 9–10 Excellent, 7–8 Pass, 5–6 Revision, 0–4 Repeat.
